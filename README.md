# Practica-Colaborativa-vane  
Trabajo colaborativo con Felipe  
Esta práctica consiste en entender cómo se trabaja de forma colaborativa en un repositorio.  
  
 ## Creación del repositorio
Al crear el repositorio, lo hicimos no vacío, con un documento README y también un archivo index.html . Este fue el archivo que se ocupó para hacer la práctica.

[ver imagen](creación-repo.png)

## Invitación al colaborador 
Después de crear el repositorio, se envió una invitación al colaborador para que se uniera al proyecto.
## Primera prueba en la rama main
Una vez que el colaborador aceptó la invitación, clono el repositorio en su computadora. Como primera prueba, el colaborador modifico directamente sobre la rama main, agregando un texto breve para ver cómo funcionaba, y logro subir ese cambio con un push directo sobre la rama main, ya que en ese momentó no existía ninguna restricción. 
#### ¿ Por qué no se recomienda hacer push directamente a main? 
No se recomienda, ya que esta representa la versión oficial y estable del proyecto. Si cualquier colaborador pudiera subir cambios sin revisión, se corre el riesgo de intorducir errores o código que rompa el proyecto sin que nadie lo revise antes.
## Implementación de la regla
 Se implementó una regla para proteger la rama main . Con esta configuración, los colaboradores deben crear un pull request y recibir aprobación antes de integrar cambios a la rama main.  
 [ver imagen](imagen-regla.png)
 ## Flujo de trabajo del colaborador 
 Con la regla ya implementada, el colaborador creó su propia rama, en la cual editó y agregó lo que consideró correcto. Una vez terminado su trabajo, creó un pull request para que sus cambios quedaran en revisión. 
 ## Revisión e integración por el dueño del repositorio
  Al crearse el pull request, le llega una notificación al dueño del repositorio. Este revisa si los cambios propuestos son correctos, y si todo está bien, los integra a la rama main. En caso de que algo no esté correcto, el dueño del repositorio puede declinar los cambios.
